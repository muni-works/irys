irys
A spectral path tracer in Rust that tells you how the image changes when the scene does.
GPU and f64 CPU tiers. Bit-exact replay. Apache-2.0.
git clone muni-works/irys Read the paper

A renderer turns a scene into an image. A differentiable renderer also says how the image would change if the scene did: if a material were rougher, a joint turned further, or a bore were a tenth of a millimetre wider. Optimisers consume that answer, so an error in it does not show as a wrong pixel. It shows as a fit that does not converge.

irys computes those derivatives by path replay. Its replay regenerates the forward pass's paths bit for bit, and every gradient has an f64 reference to check it against. A gradient test that fails therefore points to a bug, not to noise or rounding.

irys owns no geometry. You implement the Geometry trait (bounds and ray intersection) and irys does the light. It is the renderer for vcad, kosm, ipse, phyz and muni.

Spectral path tracing on the GPU

One renderer from a CPU path tracer to a wgpu compute tier.

irys traces spectra, not RGB. Each path carries four wavelengths, and at equal paths that cuts per-pixel colour noise 28.7 times. The CPU tracer covers BVH and TLAS scenes, analytic primitives, triangle meshes, heightfields, Gaussian splats and caustics. The GPU tier runs a WGSL integrator on wgpu 30.

An OpenPBR scene kernel handles volumes, skin and hair, and an importer reads scenes exported from Blender. These beauty frames are 1920 by 1080 at 4096 samples per pixel, with no denoiser.

Cycles is 2 to 3 times faster per sample on these two scenes. At equal time, irys met its target against Cycles on one of three test scenes and was 1.23 to 1.27 times behind on the other two.

Differentiable rendering with exact replay

The backward pass redraws the forward pass, bit for bit.

irys runs path replay backpropagation on a GPU wavefront, with next-event estimation and multiple importance sampling. Replay stores nothing per vertex: it regenerates each path from its seed through the same pipelines. Three choices make that regeneration exact. An integer SplitMix64 built from 16-bit limbs gives the GPU the CPU's random stream. Reductions run in a fixed order with no float atomics. The BVH walk depends only on the ray.

Memory scales with paths, not depth. A path costs 63 f64 words at depth 2 and at depth 8 alike, and a 1024 by 1024 frame at 4 samples per pixel replays bit for bit in nine chunks.

Replay is bit-exact per device and driver. Another GPU or compiler may round differently and then agrees with the CPU reference to f32 precision. Timings are from one Apple M-series machine through Metal.

An f64 reference from the same source

Write a material once. Run it on the GPU and check it in f64.

Each BSDF is a graph in the tang tensor compiler. tang lowers it to an evaluation program and an adjoint, emits WGSL for the GPU, and runs the same graph in f64 on the CPU. That separates three sources of error that are otherwise tangled together: estimator bias, device rounding and Monte Carlo noise.

The differentiable material today is a GGX conductor with a three-band spectral Fresnel. irys does not differentiate diffuse surfaces, the environment or Gaussian splats, and the environment is the only light.

Pose gradients through instanced CAD

Move a joint, and the gradient sees the silhouette, the shading and the shadow move.

A scene is a two-level BVH of CAD parts and their instances. irys samples primary edges for silhouettes and creases, differentiates the interior by forward-mode duals with frames attached to each moving part, and samples secondary edges so that shadows and reflections contribute. The same machinery differentiates a seven-parameter camera.

On the rose robot, 2.4 million triangles tessellated by vcad, a fit of the arm recovers three joint angles to within 0.07 degrees from a start 13 to 23 degrees away, on a synthetic target. On the arm over a floor, the shadow carries about 15% of the gradient; with secondary edges the gradient agrees with central differences within 1.1 standard errors.

From pixels to CAD dimensions

The derivative of an image with respect to a part's dimension.

irys computes an image gradient on every vertex of a mesh. vcad's BRep kernel takes that gradient on its frozen tessellation and pulls it back to a CAD parameter in one reverse pass. The shared benchmark is a robot shoulder plate with a 49 mm bearing bore, and the parameter is the bore diameter.

The pullback has no step size. It is exact for the frozen mesh, and the irys edge sampling error is its only noise. Recovering editable CAD from photographs is built on irys and covered in a companion paper, Seeing Is Measuring.

Quick start

Requires Rust 1.95 or newer and a C compiler on your PATH. The first build fetches tang from git and is slow. irys is not on crates.io (the irys crate there is an unrelated project), so depend on it by git. 

git clone https://github.com/muni-works/irys
cd irys

# CPU only: fit a ball's roughness and colour to one target image
# by path replay. Writes target.ppm, iter_NNN.ppm and loss.csv.
cargo run --release -p irys-diff --example fit -- out/fit

# The same fit on the GPU wavefront.
cargo run --release -p irys-diff --features gpu --example fit_gpu -- out/fit_gpu

# Tests. GPU tests skip when there is no adapter.
cargo test -p irys

Everything is version 0.1.0 and the API is not stable. The core crates are the most settled; irys-diff and the crates built on it are research code. The GPU wavefront uses wgpu's experimental ray queries, and every recorded run is on Apple silicon with Metal.

Limits

  • Replay is bit-exact per device and driver, not across them.
  • Splats and diffuse surfaces are rendered but not differentiated.
  • Only the environment emits light in the differentiable path: a sky and a sun lobe.
  • Poses move parts rigidly. Shape changes enter only through the vcad pullback.
  • All recorded timings are from one Apple M-series machine through Metal.

The paper's numbers trace to data/measured.tsv, each row naming its test and commit, and to the dated build log in docs/design.md.
