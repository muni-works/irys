irys.

Render a scene. Get the gradient. irys is a spectral path tracer that tells you how to change a material, a pose or a CAD dimension to match an image.

It runs on the GPU through wgpu, checks itself against an f64 CPU reference, and replays the forward pass bit for bit, so a seed gives the same gradient on every run.

What you can do with it.

Each of these runs today, from the examples and tests in the repository.

Fit a material to an image.

Start from a rough grey ball. After 60 gradient steps, 5 s on the GPU, irys has the target's roughness within 0.012 and its spectral colour within 0.006.

Read a robot's pose from pixels.

Three joint angles of a 2.4 M-triangle arm, recovered to 0.07° from a start 13 to 23° away. The silhouette, the shading and the shadow on the floor all feed the gradient.

1e-15agreement with vcad's own forward-mode derivative

Optimise a CAD dimension.

irys puts an image gradient on every mesh vertex, and vcad pulls it back to the diameter of a bearing bore in one reverse pass. No step size to tune.

Fit diffuse colours and splats.

The albedo of every diffuse surface and each Gaussian splat's colour and opacity are differentiable on CPU and GPU, under a sky, a sun and area lights. GPU matches the f64 reference to 5e-5.

Beauty frames from the same renderer.

Spectral, four wavelengths per path, with OpenPBR materials, volumes, skin and hair, and scenes imported from Blender.

1080p Blender scenes at 4096 spp with no denoiser. Cycles is 2 to 3 times faster per sample on these.

Ten lines to a gradient.

From examples/fit.rs: render, score against a target, and get the derivative of the loss for every material parameter.

// irys-diff, from a clone of the repository
use irys_diff::prb::{self, Kernels, L2, Scene};

let scene = Scene::new(96, 96, 8);            // a ball on a floor, 8 spp
let mut k = Kernels::new(scene.lanes(), true);
let mut theta = [0.7, 0.5, 0.5, 0.5];        // roughness, F0 at 450 / 550 / 650 nm

for it in 1..=60u64 {
    let seeds = (2 * it, 2 * it + 1);
    let (loss, grad) = prb::gradient(&scene, &theta, seeds, &mut k, &L2(&target));
    // step theta with Adam, as the example does
}

Why you can trust the gradient.

When a fit fails to converge, you need to know whether it is your problem or the renderer's.

Exact replay

The backward pass regenerates the forward pass's paths: 65 536 of 65 536 lanes bit-identical, and two runs give identical gradients.

An f64 reference

Every material is one tang graph, lowered to the GPU and run in f64 on the CPU. GPU gradients agree to 3.5e-4.

Metal and Vulkan

Developed on Apple silicon. The full test suite also passes on an NVIDIA RTX 3090 through Vulkan.

Replay is exact per device and driver; across GPUs, results agree to f32 precision. irys owns no geometry. Implement the Geometry trait and irys computes the light. It renders for vcad, kosm, ipse, phyz and muni.

Quick start.

The renderer is on crates.io as irys-render. Code still imports it as irys.

cargo add irys-render                 # CPU
cargo add irys-render --features gpu  # with the wgpu tier

The differentiable crates depend on tang-compile, which is not on crates.io yet, so run them from a clone. That needs Rust 1.95 or newer and a C compiler on your PATH, and the first build fetches tang from git.

git clone https://github.com/muni-works/irys
cd irys

# CPU only: fit a ball's roughness and colour to one target image
# by path replay. Writes target.ppm, iter_NNN.ppm and loss.csv.
cargo run --release -p irys-diff --example fit -- out/fit

# The same fit on the GPU wavefront.
cargo run --release -p irys-diff --features gpu --example fit_gpu -- out/fit_gpu

# Tests. GPU tests skip when there is no adapter.
cargo test -p irys

The irys crate on crates.io is an unrelated project. Everything is version 0.1.0 and the API is not stable. The core crates are the most settled; irys-diff and the crates built on it are research code. All timings come from Apple silicon with Metal. The test suite also passes on an NVIDIA RTX 3090 through Vulkan.
